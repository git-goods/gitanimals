# GitAnimals 조작 방지 정책 (초안)

2026-11-27 · 레벨 정책 변경, 데스크탑 앱(AI 토큰 경험치), 배틀·PvP 도입을 전제로 한 제안

## 한 줄 요약

경험치의 출처(커밋, 토큰)는 완전히 검증할 수 없다. 그래서 **출처를 믿지 않는 대신 결과를 서버가 쥔다.** 레벨·스탯·돈·배틀 결과는 서버만 계산하고 확정하며, 앱에서 오는 값은 상한과 감쇠를 거쳐 피해의 최대치를 정해 둔다.

## 왜 필요한가

- **커밋도 조작된다.** 빈 커밋 스크립트나 봇 저장소면 충분하다. 활성 유저 표본에 총 커밋 95만 개 계정이 있었다. 지금 `User.levelUpPersonas`는 들어온 커밋 수만큼 레벨을 올리고 상한이 없다.
- **AI 토큰은 유저 컴퓨터에서 잰다.** 로그 파일과 앱 메모리는 유저가 고칠 수 있다.

## 원칙

1. **잔액·레벨·스탯·배틀 결과는 서버가 원본이다.** 앱은 보여주기만 한다.
2. **앱은 결과가 아니라 사건을 보낸다.** "500원 받음", "Lv.999" 같은 값은 받지 않는다.
3. **모든 획득에는 하루 상한이 있다.** 조작해도 "부지런한 정상 유저" 수준에서 멈춘다.
4. **조작으로 얻는 이득을 줄인다.** 레벨이 배틀 승패와 돈으로 곧장 이어지지 않게 한다.
5. **막을 수 없는 것은 탐지하고 되돌린다.**

## 위협과 대응

| 위협 | 예시 | 대응 |
|---|---|---|
| 커밋 부풀리기 | 빈 커밋 자동화, 봇 저장소 | 하루 커밋 경험치 상한, 레벨이 오를수록 필요 경험치 증가 |
| 토큰 부풀리기 | 로그 수정, 토큰 낭비, 과거 기록 재전송 | 사건 단위 수집, 중복 제거, 기간 제한, 로그 감쇠, 하루 상한 |
| 레벨 몰아주기 | 합치기로 한 마리에 집중(Lv.18,866 사례) | 합치기 규칙 재검토, PvP 레벨 맞춤 |
| 돈 조작 | 세이브 수정, 상금 요청 위조 | 서버 원장, 앱은 금액을 보내지 않음, 서버 재검증 후 지급 |
| 배틀 결과 위조 | 진 판을 이겼다고 보고 | 시드 + 명령 재생 검증, PvP는 서버 판정 |
| 중복 정산 | 같은 요청 반복 전송 | 배틀 ID·사건 ID 멱등 처리 |
| 부계정 | 새 계정으로 상금·PvP 파밍 | 신규 계정 제한 |

## 정책 상세

### 1. 경험치

**커밋 (서버가 GitHub에서 직접 수집)**
- 지금 구조를 유지한다. 서버가 GitHub에서 가져오고 앱은 관여하지 않는다.
- 하루 커밋 경험치 상한을 추가한다(현재 없음).

**AI 토큰 (데스크탑 앱이 수집)**
- 누적 합계가 아니라 **사건 단위**로 보낸다: 세션·메시지 ID 해시, 시각, 모델, 토큰 수. 대화 본문과 원본 로그는 보내지 않는다.
- 서버 검증:
  - 같은 ID는 한 번만 인정한다.
  - 최근 N일 이내 사건만 받는다. 과거 기록을 몰아서 보낼 수 없다.
  - 사람이 쓸 수 없는 속도는 버린다(예: 1시간에 수천만 토큰).
- 경험치 환산은 `log(토큰)`처럼 감쇠시키고 하루 상한을 둔다.
- 하루 경험치에서 AI가 차지하는 몫은 커밋보다 작게 둔다. 커밋은 서버가 검증할 수 있고 토큰은 그럴 수 없다.

### 2. 레벨·스탯

- 레벨과 스탯은 서버가 경험치로 계산한다. 앱이 계산한 값은 표시용이다.
- 스탯 포인트 분배는 앱에서 요청하고, 서버가 남은 포인트를 확인한 뒤 확정한다.
- 레벨 합치기는 새 경험치 곡선에 맞춰 다시 정한다. 예: 레벨이 아니라 경험치의 일부를 넘긴다.

### 3. 돈

- 잔액은 서버 원장에만 있다. 로컬에 저장된 잔액은 믿지 않는다.
- 앱은 "배틀이 끝났다"만 알린다. 상금은 서버가 계산해서 지급한다.
- 모든 지급·차감은 사유와 출처 ID(배틀 ID 등)가 있는 원장 기록으로 남긴다.
- 하루 획득 상한을 둔다. 다른 방어가 뚫려도 피해가 하루 상한에서 멈춘다.

### 4. 컴퓨터 배틀 (PvE)

연출은 앱에서 부드럽게 하고, 결과는 서버가 확인한다.

1. 배틀을 시작할 때 서버가 배틀 ID와 시드를 발급한다.
2. 앱은 그 시드로 배틀을 진행하고, 끝나면 배틀 ID와 명령 목록을 보낸다.
3. 서버는 같은 시드와 명령으로 배틀을 다시 돌린다.
4. 결과가 이길 때만 상금과 경험치를 지급한다. 배틀 ID는 한 번만 정산한다.

비용: 배틀 규칙이 앱과 서버에서 똑같이 돌아야 한다. 규칙표(기술, 상성, 데미지 공식)를 데이터로 공유하고, 같은 입력에 같은 결과가 나오는지 테스트로 묶는다.

### 5. PvP

- 처음부터 끝까지 서버가 판정한다. 앱은 턴마다 명령만 보낸다.
- 서버에 있는 펫, 서버가 계산한 스탯으로만 참가한다.
- 레벨을 맞춰서 싸운다(예: 모두 Lv.50 기준). 부풀린 레벨로 이길 수 없다.
- 돈 이동은 한 트랜잭션으로 확정한다. 한 판에 걸 수 있는 금액과 하루 PvP 수익에 상한을 둔다.
- 비슷한 레벨끼리만 돈이 걸린 매칭을 한다.

### 6. 계정

- 신규 계정은 돈이 걸린 PvP와 경매를 막는다. 기준 예: GitHub 계정이 만들어진 지 30일 미만, 가입 7일 미만.
- 앱 세션은 기기별 토큰으로 관리하고, 로그아웃·탈퇴 때 폐기한다.

### 7. 탐지와 제재

- 관리자 화면에 이상 계정을 띄운다:
  - 매일 상한을 꽉 채우는 계정
  - 분포에서 크게 벗어난 계정
  - 짧은 시간에 돈이 몰리는 계정
- 확인되면 원장 기록으로 경험치·돈을 회수하거나 PvP를 막는다.

## 기대하지 않는 것

- **요청 서명, 앱 난독화**: 앱 안의 키는 꺼낼 수 있다. 시간을 조금 벌 뿐이므로 주 방어로 쓰지 않는다.
- **로컬 데이터의 진위 증명**: 하지 않는다. 대신 로컬 데이터가 돈·레벨·승패를 직접 바꾸지 못하게 한다.

## 지금 코드에서 바꿀 것 (gitanimals 백엔드)

- `User.levelUpPersonas`: 커밋 경험치 하루 상한이 없다.
- `User.mergePersona`, `mergePersonaV2`: 없앤 펫 레벨의 절반을 더해 한 마리에 몰아줄 수 있다.
- `Persona.EVOLUTION_REQUIRED_LEVEL = 100`: 새 경험치 곡선에 맞춰 다시 정해야 한다.

## 정해야 할 것

- [ ] 하루 경험치 상한 값(커밋, AI 각각)
- [ ] 토큰 → 경험치 환산 공식과 AI 몫의 비율
- [ ] 토큰 사건을 받는 기간(N일)과 속도 한도
- [ ] 컴퓨터 배틀 규칙을 앱과 서버가 공유하는 방식
- [ ] PvP 레벨 맞춤 기준과 판돈·하루 수익 상한
- [ ] 신규 계정 제한 기준
- [ ] 이상 계정 판정 기준과 회수 절차
